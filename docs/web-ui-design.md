# AutoBench Web UI 设计

2026-11-03，使用 Taste Skill 的应用界面流程重构，保留 FastAPI、原生 ES modules 和 CSS。

## 方向

采用 **Framed sheet**，seed `1126914164`，没有重抽设计方向。灰绿色顶栏承载品牌和页面标签，白色工作区向左、向右、向下各留 8px，使用 16px 圆角与轻边框，不使用面板阴影。沿用 AutoBench 的绿色作为品牌和状态色。

IBM Plex Sans 用于界面，IBM Plex Mono 仅用于文件路径、配置标识、启动项和源码。四个字体文件及其 SIL Open Font License 均随 Python 包分发，无需运行时访问字体服务。

产品辨识元素是配置向导中的实时测试计划：机器下面按配置顺序列出 UEFI 系统及启动项，再列出测试和轮次。任务数与最终检查页共同使用现有 `counts()`，修改配置立即更新，不生成额外 YAML 字段。

## 数据与使用场景

面向编排跨系统性能测试的开发者，桌面完成配置，手机查看进度与恢复操作。现有数据对象包括：

- 机器：标识、SSH 地址、端口、用户名、认证方式。
- 操作系统：标识、UEFI 启动项、继承与覆盖的连接参数。
- UnixBench：源码包、测试项、命令参数、环境变量。
- 执行轮次：每项测试的重复次数，以及系统与测试组合产生的任务数。
- 调度策略：并行机器数、等待时间与连接超时。
- 配置文件：路径、版本、草稿与保存状态。
- 环境检查：连接、启动项、运行依赖、磁盘空间。
- 运行记录：创建时间、状态、更新时间、控制器连接情况。
- 任务与事件：机器和系统分组、当前阶段、失败原因、原始日志。
- 结果产物：文件路径、大小、预览、单文件下载与归档下载。

## 各页面首先回答的问题

| 页面     | 首先回答                                     | 主要操作                                     |
| -------- | -------------------------------------------- | -------------------------------------------- |
| 测试配置 | 哪些机器与系统将执行哪些测试，一共多少任务？ | 填写连接、选择系统、设置测试、保存并检查     |
| 运行记录 | 哪次测试需要关注，能否继续或取回结果？       | 查看详情、恢复控制、继续取消、收集与下载结果 |

向导编号仅表示配置顺序，不能视为配置已通过校验。只有后端验证通过后，才显示检查通过状态与开始测试操作。

## 布局与状态

1440px 宽度下：`1440 − 16 外边距 − 64 内边距 − 2 边框 = 1358`，配置列 `1054 + 24 间隔 + 280 预览 = 1358`。配置统一使用五步引导，各步骤共用测试计划预览，不再提供独立完整工作台。步骤依次为连接机器、选择系统、设置测试、运行设置和检查运行；可直接点击步骤编辑已有配置。

所有宽度统一使用顶部标签导航；850px 以下隐藏顶栏辅助状态并将配置与计划堆叠，600px 以下 Logo 和标签分为两行，并增大表单控件与操作触点。手机上的运行记录为双行列表，创建时间、运行标识、状态、更新时间和详情操作均可见，无需横向滚动。

状态通过文字与 SVG 标记共同表达。数字列右对齐并使用等宽数字；空值不伪造数据。补充了页面标签与面板关联、当前步骤、编辑模式和字段说明的无障碍属性，以及键盘跳转到主要内容的入口。切换主页面后回到页面顶部。

## 顶部标签导航

移除左侧导航与“工作空间 / 当前页面”面包屑，保留左上角现有 Logo、产品名称及说明。顶部只设“测试配置”和“运行记录”两个固定标签；选中标签为白底、圆角顶边，与白色内容区相接，未选中标签融入灰绿色顶栏。标签不提供关闭、拖拽或新建功能。版本和服务地址合并至顶部右侧，850px 以下隐藏；600px 以下 Logo 独占第一行，标签在第二行各占一半宽度。

沿用已有 Framed sheet 方向、seed `1126914164`、IBM Plex 字体与测试计划预览，无重抽；按用户要求将原 L 形框架调整为顶部框架。配置页首先回答测试范围，运行页首先回答进度与恢复操作。

独立环境检查页面及专用前端逻辑已移除，机器与系统配置中的连接测试继续检查连接和运行环境，启动项读取与后端检查接口保持原有行为。

页面切换复用现有会话记忆，保留表单草稿、向导步骤、YAML 内容及运行详情选择；切换后回到页面顶部。旧会话中的 `inspect` 和未知页面统一回退至测试配置。页面初始化完成前不显示错误页面。主导航使用 `tablist`、`tab`、`tabpanel` 与 `aria-selected`，只有选中标签参与 Tab 焦点顺序；左右方向键循环切换，Home/End 跳至首尾标签，Tab 进入当前页面。

本次验收：浏览器测试 64 项全部通过，覆盖标签键盘切换、旧页面记忆回退、初始化防闪现、表单和 YAML 草稿保留、运行详情恢复，以及原有连接测试与执行流程。常规测试 361 项通过、2 项跳过。Ruff、ESLint、Prettier 和 Git 空白检查通过。

在 1440、768、390px 对五步配置与运行记录复查，共保存 21 张截图，无页面横向溢出或 JavaScript 异常。Taste Skill 浏览器检查为 0 FAIL、1 WARN：继续保留路径、版本与辅助说明的 12px 字号；源码检查为 0 FAIL，提示保留的补零用于配置标识，等宽字体用于标识和代码，阴影仅用于菜单与浮层。截图与报告位于 `.taste-skill/tabs-screens/` 和 `.taste-skill/tabs-inspect/`。沿用仓库示例配置与本地已有运行记录，未创建演示运行或写入用户 YAML。

## 五步引导整合

机器管理在连接机器和选择系统两步提供；测试配置的排序和删除集中在设置测试步骤。结果目录及全部调度设置集中在第四步，最终检查与启动测试位于第五步。打开、导入及刷新配置统一进入第一步，YAML 切换保留当前步骤。机器、系统、测试和运行设置错误分别回到对应步骤，自动展开高级字段；未知字段继续在 YAML 中修正。
